# Scribe

[Download Android App](https://github.com/n06-nitin/scribe-the-note-taker/releases/download/App/app-release.apk)

Record a conversation, get back a clean, professionally formatted note — who said what, summarized, with action items pulled out. Bring your own API keys.

## What's implemented

- **Recording** — tap-to-start/stop capture (`src/audio/useRecordingSession.ts`), nothing records in the background unless a recording session is explicitly active.
- **Transcription + diarization** — recordings are sent to **Deepgram** (`src/services/deepgram.ts`) for speech-to-text with speaker clustering ("Speaker 0", "Speaker 1", ...) within that one recording.
- **Speaker labeling** — diarized clusters are written out as `Unknown1`, `Unknown2`, etc. by default (`src/services/recordingPipeline.ts`).
- **Named speaker enrollment — fully free, fully on-device, no account of any kind.** The Speakers tab records one 15-second clip per person (auto-stops, no manual timing) and runs it through an open-source speaker-embedding model (WeSpeaker's ECAPA-TDNN, Apache-licensed, ~25MB, bundled straight into the app) via ONNX Runtime, entirely on the phone (`modules/voice-embed`, `src/services/enrollment.ts`). One clip is enough — the model natively handles variable-length utterances, so there's no accuracy reason to record several short takes and average them. The embedding is stored as a plain JSON float array in SQLite. No API key, no vendor account, no network call — ever. (This is the third design here: Azure AI Speaker Recognition was retired 2025-09-30; Picovoice's free tier was sunset 2026-06-30. Going open-source and on-device was the way to stop depending on any vendor's pricing or continued existence — see "Known gaps" for how the feature-extraction math was verified.) Enrollment works end-to-end; using a saved voiceprint to *automatically* relabel `Unknown#` as a real name during a live multi-speaker recording is not wired up yet — but any `Unknown#` label can be renamed **manually** on a per-note basis (tap the speaker chip or the label in the transcript), either typing a name or picking an enrolled speaker; this only relabels that one note's segments, it doesn't retroactively teach the app to recognize that voice elsewhere.
- **Enrollment sanity-checking** — since the embedding itself is an opaque 192-dim vector, the app also surfaces two human-checkable numbers: a rough per-clip pitch estimate (`modules/voice-embed`'s `PitchEstimator.kt`, time-domain autocorrelation, shown live during enrollment and averaged on the Speakers list), and a **voice comparison** card on the Speakers tab showing the actual pairwise cosine similarity between every pair of enrolled speakers — the same number the app would use for matching, so you can visually confirm two different people really do read as numerically distinct.
- **Summarization** — the raw transcript is sent to whichever of **OpenAI / Claude / Groq** you've selected in Settings, with a model dropdown per provider (`src/services/llm.ts`, `src/services/providers.ts`). The model is required to return **strict, schema-validated JSON** (`src/services/schemas.ts`, using Zod — TypeScript's equivalent of Pydantic) with distinct sections: `title`, `overview`, `keyPoints[]`, `actionItems[]`, `reminders[]`. If the model's response doesn't match the schema, parsing throws a clear error instead of silently corrupting a note.
- **Offline-safe inbox with visible failures and manual retry** — every recording's transcript is written to a local `inbox_queue` SQLite table before summarization is attempted (`src/db/inboxRepo.ts`). If you're offline or the AI call fails, it stays queued; a `NetInfo` listener and saving a new API key in Settings both trigger an automatic retry (`src/services/inboxFlush.ts`). If a note is stuck — no Deepgram key, bad LLM key, no speech detected, etc. — it's flagged with a red "needs retry" chip on the Notes list and Home screen, and the note detail screen shows the actual error message plus a manual **Retry** button (`retryOne()` for a failed summarization, `retryTranscription()` for a failed transcription). The original recording is copied into the app's document directory (`src/services/recordingPipeline.ts`) specifically so a failed transcription can be retried without re-recording.
- **Notes** — stored locally in SQLite (`src/db/notesRepo.ts`), rendered as distinct sections (`src/components/NoteSections.tsx`) with a collapsible full transcript, each line timestamped (`formatDurationMs`) against the start of the recording. The original audio is kept (`note.audioUri`) specifically so you can play it back in-app (`src/components/AudioPlayback.tsx`, `expo-audio`'s playback hooks) — including on notes where transcription or summarization failed, so you're never locked out of what was actually said just because the pipeline choked on it. It's deletable independently of the note itself ("Delete recording" — frees space, keeps the transcript/summary, but means a failed note can no longer be retried).
- **Reminders — full management, not just fire-and-forget** — the same summarization call asks the model to pull out concrete future events ("meet at 6pm tomorrow") and resolve them to an absolute datetime using the conversation's actual recorded time as the reference point (so "tomorrow" resolves correctly). Each one gets scheduled as a real local device notification a configurable number of minutes beforehand (default 10) via `expo-notifications` (`src/services/reminders.ts`). Reminders persist in SQLite (`src/db/remindersRepo.ts`) independent of notification delivery, and get re-armed on app startup if the OS-level notification ever goes missing (reinstall, cleared storage) via `reconcileScheduledReminders()`. The **Notes tab** has a dedicated **Reminders** view (segmented alongside Notes) listing every reminder across every note, each with delete and "change time" (native Android date/time picker, `@react-native-community/datetimepicker`). Tapping a reminder notification opens the app straight to that note (`Notifications.addNotificationResponseReceivedListener` + `getLastNotificationResponseAsync` for cold starts, wired in `app/_layout.tsx`). An earlier pass also added "+5m/+20m/+1h" snooze buttons, but pulled them back out: `expo-notifications` can't reliably put action buttons on the notification itself on Android (its own types mark that iOS-only), so the buttons lived in-app instead — which meant tapping "+5m" on a reminder that hadn't fired yet silently meant "remind me 5 minutes from now" rather than anything about the event's own time, and that wasn't obvious from the UI. Change time covers the same need without the confusion.
- **Resummarize** — renaming a speaker label (see above) only touches the transcript segments; the written summary was already generated with the old label. A "Resummarize" action (prompted automatically right after a rename, or available any time on a ready note) re-runs the LLM call against the current segments and replaces the summary. It also clears and re-extracts reminders for that note, so a resummarize doesn't leave duplicate reminders behind.
- **Floating launcher (Android only) — records for real, no app UI needed.** A local Expo Module (`modules/overlay-bubble`) draws a small translucent bubble over other apps using `SYSTEM_ALERT_WINDOW` + a `microphone`-type foreground service. Tap it once to start recording — capture happens right there via `AudioRecord` (`BubbleAudioRecorder.kt`, same technique as `voice-embed`, writing a plain WAV file), completely independent of whether the app is open. Tap again to stop; the finished recording is handed to the normal transcribe→summarize pipeline via an Expo Modules event (`onRecordingReady`, wired in `app/_layout.tsx`) exactly as if you'd used the in-app record button. The bubble itself changes color and the persistent notification's text changes between idle and recording, so there's always an explicit, hard-to-miss signal something is being captured. Long-press the bubble while idle to remove it (fires `onBubbleDismissed`, which flips the Settings toggle off too). See "Known gaps" for the one real limitation of this design, and "Why no iOS bubble" for why this is Android-only.
- **Crash containment** — a root `ErrorBoundary` (`src/components/ErrorBoundary.tsx`) catches render-time exceptions anywhere in the tree and shows a recoverable screen instead of a blank crash.

## Setup

You'll need your own keys for whichever services you use — nothing is bundled:

| Service | Used for | Where to get a key |
|---|---|---|
| Deepgram | Transcription + diarization | console.deepgram.com |
| OpenAI / Anthropic / Groq | Summarization + reminder extraction (pick one) | platform.openai.com / console.anthropic.com / console.groq.com |

Speaker enrollment and reminders need **no key at all** — enrollment runs entirely on-device (`modules/voice-embed`), and reminders use the device's local notification system (`expo-notifications`); just grant the notification permission the first time you open the app (or from **Settings → Reminders** if you skipped it).

Enter all of these in the app under **Settings** — they're stored with `expo-secure-store` (Keychain/Keystore), never hardcoded or sent anywhere but the respective provider's API.
